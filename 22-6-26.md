# Infrastructure Tasks

## 1. Route Mismatch in Kubernetes Ingress

### Problem

Some application routes were not being matched correctly by the NGINX Ingress configuration, resulting in incorrect routing and 404 responses.

### Resolution

- Analyzed the existing Ingress path configuration.
- Updated Ingress rules to use regex-based path matching.
- Configured routing to properly handle dynamic and nested routes.
- Verified routing behavior across all application endpoints.

### Result

- Route matching works correctly for all application paths.
- Dynamic routes are forwarded to the appropriate backend services.
- Route mismatch and 404 errors were eliminated.

## 2. HTTPS Certificate Warning (Self-Signed Certificate) ⚠️

### Problem

The application is currently using a self-signed SSL certificate. Since the certificate was not issued by a trusted Certificate Authority (CA), browsers display security warnings and mark the connection as untrusted.

### Investigation

- Verified that the TLS certificate configured in the Ingress is self-signed.
- Confirmed that browsers reject the certificate because it is not signed by a trusted CA.

### Proposed Solution

- Configure Cert Manager in the Kubernetes cluster.
- Integrate Let's Encrypt as the Certificate Authority.
- Update the Ingress resource to request and use a trusted TLS certificate.
- Validate HTTPS access after certificate issuance.

### Current Status

- Issue identified.
- Solution approach finalized.
- Implementation pending.
