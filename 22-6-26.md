## Issue 1: Route Mismatch in Kubernetes Ingress

#### Problem Statement

Several application endpoints were not being routed correctly by the NGINX Ingress Controller, resulting in routing inconsistencies and HTTP 404 responses.

#### Root Cause Analysis

The existing path matching configuration was not handling dynamic and nested routes correctly, causing requests to be matched against unintended backend services.

#### Resolution

* Reviewed existing ingress path definitions.
* Implemented regex-based path matching rules.
* Updated routing configurations to support dynamic and nested URL structures.
* Performed validation across all affected application endpoints.

#### Result

* Correct request routing across all application services.
* Elimination of route mismatch issues and related 404 responses.
* Improved reliability of ingress-based traffic management.

## Issue 2: HTTPS Certificate Trust Warning (Open)

#### Problem Statement

The application is currently secured using a self-signed TLS certificate. As the certificate is not issued by a trusted Certificate Authority (CA), browsers display security warnings and classify the connection as untrusted.

#### Impact

* Browser security warnings during application access.
* Reduced user trust in the HTTPS connection.
* Potential issues for external integrations that require trusted certificates.

#### Findings

* The current certificate was generated internally and is self-signed.
* Certificate validation fails because the issuing authority is not recognized by standard browser trust stores.

#### Planned Resolution

* Deploy Cert Manager within the Kubernetes cluster.
* Configure Let's Encrypt as the certificate issuer.
* Automate certificate issuance and renewal.
* Update ingress resources to utilize CA-signed certificates.
