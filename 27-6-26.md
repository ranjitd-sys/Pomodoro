# FBA Workflow Machine

## Overview
An XState machine that automates Amazon FBA Removal processing using Effect-TS actors.

## Flow

```
fetch → [has data] → selectFBA → [both fileIds] → write → done
      → [no data]  → dailyFBA                   →        done
      → [error]    → error
```

## States

| State | Description |
|-------|-------------|
| `fetch` | Checks DB for existing FBA data |
| `selectFBA` | Fetches fileIds using date from DB |
| `dailyFBA` | Runs when no existing data found |
| `write` | Writes FBA data using fileIds |
| `done` | Terminal success state |
| `error` | Terminal error state |

## Actors

### `fetchActor`
- Queries `fba_removable` table
- Returns `{ hasData, fromDate }`
- `hasData: true` → go to `selectFBA`
- `hasData: false` → go to `dailyFBA`

### `SelectFBAactor`
- Reads `fromDate` from DB
- Computes date range:
  - If `fromDate` exists: `startDate = fromDate`, `endDate = fromDate + 1 day`
  - Fallback: `startDate = now - 2 days`, `endDate = now - 1 day`
- Runs `AmazonFBARemovalShipmentWorkflow` and `AmazonFBARemovalDetailWorkflow`
- Returns `{ hasData, fbaRemovalShipmentFileId, fbaRemovalDetailFileId }`
- `hasData` is `true` only when both fileIds are non-null
- Sends Google Chat notification with result

### `DailyFBAactor`
- Runs when no existing FBA data found in DB
- Computes date range from `now` (no DB input needed)
- Runs both FBA workflows
- Sends Google Chat notification

### `writeVendor`
- Receives `{ detailFileId: number, shipmentFileId: number }` via actor input
- Runs `AmazonVendorReturnWriteWorkflow`

## Context

```typescript
{
  fromDate: Date | null,
  fbaRemovalShipmentFileId: number | null,
  fbaRemovalDetailFileId: number | null,
}
```

## Key Patterns

- `fromEffect(_ref, input)` — positional args, not destructured `{ input }`
- `Effect.orDie` — converts typed errors to defects so error channel is `never`
- `DateTime.fromDateUnsafe(date instanceof Date ? date : new Date(String(date)))` — safe DB date conversion
- `guard` on `onDone` array — first matching guard wins, no guard = always matches
- fileIds stored as `number` in context, cast with `Number()` when assigning from string
