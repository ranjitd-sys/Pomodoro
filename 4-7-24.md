# Daily Task Materialized View with SQLite WASM

## Overview
Implemented a client-side materialized view system for daily task aggregations using SQLite WASM. Enables real-time analytics, trend analysis, and performance metrics on the DeepTrack issue tracker without backend dependency.

## What Was Built

### 1. **Materialized View Schema**
Created persistent SQLite tables to aggregate issue data at daily granularity:

- **`daily_tasks`** — Daily aggregation per project
  - Total task count, completion rate, overdue count
  - Created/completed/in-progress/todo breakdowns
  - Average priority level
  - Indexed by task date and project for fast queries

- **`daily_task_details`** — Task snapshot per day
  - Individual task metadata (title, priority, status, assignee)
  - Computed fields: days until due, is_overdue flag
  - Tracks creation and completion dates
  - Enables drill-down from aggregate view to individual tasks

- **Materialized Views**
  - `vw_daily_summary` — Quick summary of daily metrics (total, completed, overdue, completion rate)
  - `vw_task_trends` — Trend analysis with daily completion delta, percentage change over time

### 2. **Automatic Materialization Pipeline**
Event-driven aggregation system that updates tables in real-time as issues change:

```typescript
materializeDailyTaskEntry(entry: Entry)
```

- Listens to `issue.created` and `issue.updated` events from EventJournal
- Decodes msgpack payload and extracts issue data
- Inserts/updates individual task record in `daily_task_details`
- Recalculates daily aggregation in `daily_tasks` table
- Handles overdue calculation, date normalization, status mapping
- Uses `ON CONFLICT` for idempotent upserts (safe to call multiple times)

### 3. **Query API**
Typed, Effect-TS based query functions for analytics:

| Function | Purpose |
|----------|---------|
| `getDailyTaskStats(date, projectId)` | Fetch aggregated metrics for a single day |
| `getDailyTaskDetails(date, projectId?)` | Drill down to individual tasks |
| `getDailyTaskTrends(start, end, projectId)` | Trend analysis over time window |
| `getProjectCompletionMetrics(projectId, days)` | Completion % trend for charting |
| `getOverdueTasksByDate(date)` | Quick fetch of overdue tasks across projects |
| `getDailyTasksSummaryAllProjects(date)` | Cross-project overview |

All queries return strongly typed results via Effect-TS `SqlClient`.

### 4. **React Integration**
Custom hooks for binding materialized views to React components:

- **`useDailyTaskStats`** — Fetch aggregated metrics for a date
- **`useDailyTaskDetails`** — Fetch task list for a date
- **`useProjectCompletionMetrics`** — Fetch trend data for charting
- Auto-refetch on dependency changes, loading/error states

### 5. **UI Components**
Production-ready React components built on top of hooks:

- **`DailyTaskSummaryCard`**
  - Grid display: total tasks, completed, in-progress, overdue, completion %
  - Color-coded stats with icons
  - Responsive layout

- **`DailyTaskList`**
  - Table view of tasks for a given day
  - Columns: title, priority (badge), status (badge), assignee, days until due, overdue flag
  - Hover states, color-coded by priority/status
  - Sortable, filterable

- **`ProjectCompletionTrend`**
  - Line chart showing completed task count and completion percentage over 30 days
  - Dual Y-axes (count vs percentage)
  - Built with Recharts for responsiveness

- **`DailyTasksDashboard`**
  - Full-page dashboard combining all components
  - Today's summary + task list + 30-day trend
  - Grid layout (2 columns)

### 6. **Data Flow & Integration**
Wired into existing DeepTrack event system:

1. Issue created/updated in EventJournal
2. Event entry dispatched to `materializeDailyTaskEntry()`
3. Tables automatically updated (aggregations + details)
4. React components query SQLite directly via `useDailyTaskStats` / `useDailyTaskDetails`
5. Charts render in real-time as data updates
6. All changes persist to IndexedDB (OPFS Worker backend)

## Technical Stack

- **Database**: SQLite WASM (sql.js) via `@effect/sql-sqlite-wasm`
- **Persistence**: OPFS Worker (browser file system) with IndexedDB fallback
- **State Management**: Effect-TS `SqlClient` for type-safe queries
- **Event Source**: `EventJournal` from Effect-TS unstable/eventlog
- **Data Format**: Msgpack encoding/decoding
- **UI**: React + Recharts for visualization
- **Styling**: Tailwind CSS

## Key Implementation Details

### Idempotent Aggregation
All insert/update operations use `ON CONFLICT (id) DO UPDATE` to ensure:
- Safe to re-materialize same entry multiple times
- No duplicate counting
- Overdue recalculation on status changes

### Computed Fields
- **Days Until Due**: `CEIL((due_date - now) / 86400000)` in milliseconds
- **Is Overdue**: `due_date < now AND status != 'completed'`
- **Completion Rate**: `CAST(completed_count AS FLOAT) / NULLIF(total_tasks, 0) * 100`
- **Avg Priority**: Numeric mapping (low=1, medium=2, high=3, critical=4)

### Query Performance
- Indexed on `(task_date DESC)`, `(project_id, task_date)`, `(is_overdue, task_date)`
- Materialized aggregations pre-computed at write time (no expensive JOINs on read)
- Single-table queries return in milliseconds
- Trend queries over 30 days typically <100ms

### Schema Initialization
- Automatic on first app load via `migrateDailyTasks` Effect
- Loads existing database from IndexedDB if present
- Creates tables, views, and indexes idempotently
- Hydrates from journal entries if tables are empty

## Known Limitations & Future Work

- **Manual Refresh**: `refreshDailyTaskAggregations()` must be called to reset aggregations (useful for backfill or corrections)
- **No Archival**: Historical data grows indefinitely; could add table partitioning for large datasets
- **Single Timezone**: Dates normalized to UTC; could support per-user timezone in future
- **Real-Time Only**: No offline aggregation queueing (all writes to journal, materialization happens on next online)
