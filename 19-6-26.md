## 1. NGINX Ingress Controller Deployment ✅

### Objective

Deploy an NGINX Ingress Controller in front of the Azure Load Balancer to manage incoming traffic and route requests to Kubernetes services.

### Implementation

#### Install NGINX Ingress Controller

```sh
helm repo add ingress-nginx https://kubernetes.github.io/ingress-nginx
helm repo update

helm install ingress-nginx ingress-nginx/ingress-nginx \
  --namespace ingress-nginx \
  --create-namespace \
  --set controller.service.type=LoadBalancer
```

#### Create TLS Certificate

```sh
openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
  -keyout tls.key -out tls.crt \
  -subj "/CN=20.11.0.1" \
  -addext "subjectAltName=IP:20.11.0.1"

kubectl create secret tls my-tls-secret \
  --cert=tls.crt \
  --key=tls.key \
  -n default
```

#### Configure Ingress Resource

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: my-app-ingress
  namespace: default
  annotations:
    nginx.ingress.kubernetes.io/ssl-redirect: "true"
    nginx.ingress.kubernetes.io/force-ssl-redirect: "true"
spec:
  ingressClassName: nginx

  tls:
    - secretName: my-tls-secret

  rules:
    - http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service:
                name: my-app-svc
                port:
                  number: 80
```

### Result

* NGINX Ingress Controller successfully deployed.
* Azure Load Balancer provisioned automatically.
* TLS certificate created and attached to the Ingress.
* HTTP requests are redirected to HTTPS.
* Application traffic is routed through the Ingress Controller.

**Status:** Completed
