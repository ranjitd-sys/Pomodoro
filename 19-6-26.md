# Infrastructure Tasks

## 1. NGINX Ingress Controller Deployment ✅

### Objective

Place an NGINX Ingress Controller in front of the Azure Load Balancer to manage incoming traffic and route requests to Kubernetes services.

### Implementation

#### Install NGINX Ingress Controller

```sh
helm repo add ingress-nginx https://kubernetes.github.io/ingress-nginx
helm repo update

helm install ingress-nginx ingress-nginx/ingress-nginx \
  --namespace ingress-nginx \
  --create-namespace \
  --set controller.service.type=LoadBalancer
```

#### Create TLS Certificate

```sh
openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
  -keyout tls.key -out tls.crt \
  -subj "/CN=20.11.0.1" \
  -addext "subjectAltName=IP:20.11.0.1"

kubectl create secret tls my-tls-secret \
  --cert=tls.crt \
  --key=tls.key \
  -n default
```

#### Configure Ingress Resource

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: my-app-ingress
  namespace: default
  annotations:
    nginx.ingress.kubernetes.io/ssl-redirect: "true"
    nginx.ingress.kubernetes.io/force-ssl-redirect: "true"
spec:
  ingressClassName: nginx

  tls:
    - secretName: my-tls-secret

  rules:
    - http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service:
                name: my-app-svc
                port:
                  number: 80
```

### Result

* NGINX Ingress Controller successfully deployed.
* Azure Load Balancer provisioned automatically.
* TLS certificate created and attached to the Ingress.
* HTTP requests are redirected to HTTPS.
* Application traffic is routed through the Ingress Controller.

**Status:** Completed

## 2. Enable External HTTPS Access ⏳

### Objective

Allow external HTTPS traffic (TCP 443) to reach the NGINX Ingress Controller through the Azure Network Security Group (NSG).

### Current Issue

Although TLS is configured inside Kubernetes, external HTTPS requests cannot reach the cluster because port 443 is not accessible from the internet.

While attempting to inspect the Network Security Group, the following Azure permission error was encountered:

```sh
az network nsg list \
  --resource-group MC_Workflows_workflow_southafricanorth \
  -o table
```

```text
(AuthorizationFailed)

The client 'Ranjit@maheshdeepinsight.onmicrosoft.com'
does not have authorization to perform action
'Microsoft.Network/networkSecurityGroups/read'
over the requested scope.
```

### Root Cause

The current Azure account does not have sufficient permissions to:

* View Network Security Groups
* Modify inbound security rules
* Open port 443 for HTTPS traffic

As a result, the required NSG configuration cannot be completed.

### Required Changes

An Azure administrator or user with appropriate permissions must:

1. Locate the NSG associated with the AKS Load Balancer.
2. Add an inbound rule allowing:

   * Protocol: TCP
   * Port: 443
   * Source: Internet
   * Action: Allow
3. Verify that the Azure Load Balancer forwards HTTPS traffic correctly.
4. Optionally grant **Network Contributor** access if ongoing network management is required.

### Recommended Resolution

#### Option A — Azure Administrator Action

Ask a user with **Owner** or **Contributor** permissions on the Azure subscription to:

* Open inbound TCP port 443 in the AKS Network Security Group.
* Verify Load Balancer connectivity.
* Grant **Network Contributor** role on:

```text
MC_Workflows_workflow_southafricanorth
```

if future network configuration changes are expected.
