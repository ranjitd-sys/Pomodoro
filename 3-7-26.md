# DeepTrack Issue Linking Feature

## Overview
Built bidirectional issue relationship/linking system for DeepTrack issue tracker. Allows tasks to be linked together during creation and from the sidebar detail view with a visual topology graph.

## Features Implemented

### 1. **Timeline/Schedule Change Tracking**
- Tasks now support `startDate` and `dueDate` fields for scheduling
- Interactive calendar picker in task creation form with month navigation
- Date range selection: click first date for start, click second date for due (auto-sorts)
- Can set independent start/due times via time inputs (12-hour format)
- Progress bar visualization in task list showing completion % based on current time vs. date range
- Overdue badge appears in red when task exceeds `dueDate` and not completed
- Timeline display format: "Jul 3 — Jul 15" shown in list and sidebar
- Past dates disabled in calendar picker (greyed out, non-clickable)

**Payload changes:**
```typescript
interface IssueEntry {
  ...
  startDate?: string;  // ISO string "2026-07-03T14:30"
  dueDate?: string;    // ISO string "2026-07-15T18:00"
}
```

### 2. **Create Task with Instant Link**
- New task creation form now includes a "Relations" dropdown selector
- When creating a new task, users can immediately select a target task to link to
- Link is established **before form closes** — new task opens in sidebar already showing the relation
- Reciprocal link automatically created (A→B also creates B→A)

### 2. **Sidebar Relation Visualization**
- **Relations Topology Map**: SVG graph showing linked tasks in a circular layout around the current task
- Interactive nodes — hover to highlight, click to navigate to related task
- Animated flowing wire effect between center and connected nodes
- Color-coded by task status (todo, in-progress, completed, etc.)
- Shows up to N related tasks; falls back to list view if graph is empty

### 3. **Bidirectional Linking**
- Link one task to another → both tasks automatically reference each other
- Removing a link removes it from both sides
- Prevents duplicate relations (uses `Set` dedup in journal write)

### 4. **Relation Management**
- **Add relations**: "+" button in sidebar opens searchable task picker
- **Remove relations**: Hover list items in sidebar to reveal "×" delete button
- Graph nodes are clickable — selecting one navigates to that task
- Relation picker searchable by task title

## Code Changes

### Files Modified

#### 1. `eventjournal/write.ts`
**Added/Fixed:**
- `writeIssue()` now **returns the created entry** (with `id`/`primaryKey`) so caller can reference it
- `linkIssues()` — bidirectional link writer with duplicate prevention
- `unlinkIssues()` — bidirectional unlink with cascade removal
- `readAllIssues()` already maps `relations: []` field from journal entries
- **Removed duplicate journal.write calls** in link/unlink functions

**Key fix:** `linkIssues_` and `unlinkIssues_` now fetch fresh `allIssues` from journal before writing, avoiding stale React state closure bugs

#### 2. `useIssues.ts`
**Changed:**
```typescript
// addIssue now returns the created entry
const addIssue = async (payload: ...) => {
  const created = await runClientPromise(
    writeIssue({ ...payload, project: currentProject! })
      .pipe(Effect.tap(() => Effect.sync(load))),
  );
  return created;
};

// linkIssues_/unlinkIssues_ fetch fresh state to avoid stale closures
const linkIssues_ = async (fromId: string, toId: string) => {
  const fresh = await runClientPromise(readAllIssues);
  await runClientPromise(linkIssues(fromId, toId, fresh as IssueEntry[]));
  load();
};
```

#### 3. `DeepTrackMachineEffect.tsx` (main View)
**Added to machine context:**
- `ExtendedWorkspaceContext` with `isCalendarOpen` and `viewDate` for calendar state

**New form fields:**
- "Relations" dropdown (2-column span) in task creation form listing all tasks
- Selecting a task sets `ctx.relatedTaskId`
- "Schedule / DateTime Range" calendar picker with:
  - Month/year navigation buttons (← →)
  - Grid of clickable day cells (past dates disabled)
  - Dual time inputs for start/due times (HH:MM format)
  - Date range display button showing "Pick a date range" or "Jul 3 — Jul 15"
  - Highlighted start/due dates in the calendar, shaded range between them

**Machine context extensions:**
```typescript
interface ExtendedWorkspaceContext extends WorkspaceContext {
  isCalendarOpen: boolean;      // Calendar popover visibility
  viewDate: Date;               // Currently displayed month (default: July 2026)
  startDate: string;            // ISO string with time
  dueDate: string;              // ISO string with time
}
```

**New events:**
- `CHANGE_MONTH` — navigate calendar forward/backward by month offset
- Handled via `UPDATE_FIELD` for `startDate`, `dueDate`, `isCalendarOpen`

**New `handleAdd` logic:**
```typescript
const newIssue = await addIssue({ ... });
let issueToShow = newIssue;

if (ctx.relatedTaskId && newIssue?.id) {
  issueToShow = {
    ...newIssue,
    relations: [...(newIssue.relations ?? []), ctx.relatedTaskId],
  };

  await linkIssues_(newIssue.id, ctx.relatedTaskId);

  // Reciprocal update if target is already open
  if (ctx.selectedIssue?.id === ctx.relatedTaskId) {
    send({
      type: "SET_SELECTED_ISSUE_RAW",
      issue: {
        ...ctx.selectedIssue,
        relations: [...(ctx.selectedIssue.relations ?? []), newIssue.id],
      },
    });
  }
}

send({ type: "CLOSE_FORM" });
send({ type: "SELECT_ISSUE", issue: issueToShow }); // Open new task in sidebar
```

**Task list timeline visualization:**
- Each task with `startDate`/`dueDate` shows a progress bar (1.5px height, blue/red/green)
- Progress % calculated: `(now - start) / (due - start) * 100`
- Color logic:
  - **Emerald** if `status === "completed"` (with checkmark shadow)
  - **Red** if overdue (`now > due`) and not completed
  - **Blue** otherwise (hover brightens to lighter blue)
- Overdue badge: red "OVERDUE" label overlaid on progress bar
- Tasks without dates show static date string on the right

**Sidebar detail view (right panel):**
- "Relations Topology Map" section with SVG visualization
- "+ Add" button opens searchable task picker modal
- List of linked tasks with individual unlink buttons
- Nodes clickable to navigate
- Properties panel shows created date, assignee, priority, status (no timeline display in sidebar, but dates editable in form)

## Data Model

### IssueEntry Type
```typescript
interface IssueEntry {
  id: string;                    // primaryKey from journal
  title: string;
  priority: IssuePriority;
  status: IssueStatus;
  assignee: string;
  tags: Tag[];
  comments: number;
  date: string;
  project: string;
  startDate?: string;
  dueDate?: string;
  relations: string[];           // Array of linked task IDs (NEW)
}
```

### Journal Events
- `issue.created` — new task written with initial payload (no relations yet)
- `issue.updated` — task modified, includes updated `relations` array

## UX Flow

### Creating a Task with Link
1. Click "+ New Task" button
2. Fill title, priority, status, tags, dates
3. Open "Relations" dropdown → select a task from the list
4. Click "Save Task"
5. **Result:** New task opens in sidebar immediately, showing the linked task in the Topology Map

### Managing Relations from Sidebar
1. Open a task in the right sidebar
2. Scroll to "Relations Topology Map" section
3. Click "+ Add" → search and select a task → it appears in the graph and list
4. Hover a list item → click "×" to remove the link (reciprocal removal)
5. Click a graph node → navigates to that task

---

## Known Behaviors

- **Fresh state reads**: `linkIssues_`/`unlinkIssues_` always fetch latest `allIssues` from journal to avoid stale React closures
- **Instant sidebar open**: New tasks open in sidebar immediately after creation (before `load()` refresh cycle completes)
- **Bidirectional enforcement**: All link/unlink operations affect both sides automatically
- **Graph rendering**: Only shows if `relations.length > 0`; falls back to simple list otherwise
- **Deduplication**: Uses `Set` to prevent duplicate relation IDs in journal writes
