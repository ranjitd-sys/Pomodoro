### 1. Fixed Missing Input Propagation in PDF Parser Workflow

Identified and fixed an issue where the PDF parser actor was being invoked without receiving the uploaded file path.

#### Problem

The `FIRSTCRY_COMPLETED` event contained `filePaths`, but the value was never forwarded to the actor input.

```ts
// Event payload
{
  type: "FIRSTCRY_COMPLETED",
  filePaths: string[]
}
```

As a result:

```ts
pdfParserActor_
```

was always receiving:

```ts
{
  cdnLink: undefined
}
```

#### Solution

Added validation before transitioning and passed the uploaded file path into the actor.

```ts
FIRSTCRY_COMPLETED: {
  target: "pdfParser",
  guard: ({ event }) =>
    !!(event as { filePaths?: string[] }).filePaths?.length,
}
```

```ts
pdfParser: {
  invoke: {
    src: "pdfParserActor_",
    input: ({ event }) => ({
      cdnLink: event.filePaths[0],
    }),
  },
}
```

#### Outcome

* Prevented invalid PDF parser executions.
* Ensured uploaded files are correctly processed.
* Added guardrails against empty file uploads.

### 2. Added Failure Notification Flow for Workflow Pipelines

Fixed a workflow reliability issue where pipeline failures were only logged and never surfaced to operations.

#### Problem

The following events were silently ignored:

```ts
FLIPKART_FAILED
MEESHO_FAILED
FIRSTCRY_FAILED
```

Failures were logged but no notification was sent.

#### Solution

Aligned failure handling with the existing unauthorized flow by routing failures to the email notification actor.

```ts
FLIPKART_FAILED: {
  target: "sendingEmail",
}
```

```ts
MEESHO_FAILED: {
  target: "sendingEmail",
}
```

```ts
FIRSTCRY_FAILED: {
  target: "sendingEmail",
}
```

#### Outcome

* Pipeline failures now generate alerts.
* Reduced risk of unnoticed workflow failures.
* Improved operational visibility and incident response.

## Key Learnings

### Workflow Reliability

* Always validate event payloads before actor invocation.
* Failure paths should trigger operational alerts, not only logs.

### Durable Streams

* Streams provide append-only event storage with replay support.
* Consumers can resume processing from specific offsets.
* Useful for workflow orchestration, event sourcing, and distributed coordination.

### Infrastructure

* Dockerized local environments significantly reduce debugging time.
* Running the same service locally and on Kubernetes simplifies deployment validation.
