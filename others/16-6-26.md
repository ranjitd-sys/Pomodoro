### 1. Added PostgreSQL Migration for Event Storage

Implemented database migrations for persistent event storage in PostgreSQL.

#### Schema Design

```ts
CREATE TABLE IF NOT EXISTS event_log (
  id          BIGSERIAL PRIMARY KEY,
  stream_id   TEXT NOT NULL,
  seq_num     TEXT UNIQUE,
  event_name  TEXT,
  args        JSONB NOT NULL DEFAULT '{}',
  created_at  TIMESTAMPTZ DEFAULT now()
)
```

#### Indexing

```ts
CREATE INDEX IF NOT EXISTS event_log_stream_idx
ON event_log (stream_id, id);

CREATE INDEX IF NOT EXISTS event_log_name_idx
ON event_log (event_name);
```

#### Improvements

* Added persistent event storage.
* Added indexes for stream-based and event-based lookups.
* Added unique constraint on `seq_num` to prevent duplicate event ingestion.
* Optimized for event replay and stream reconstruction.

### 2. Researched and Documented Effect EventLog Architecture

Spent time understanding the internal architecture and synchronization model of Effect EventLog.

#### Key Concepts Explored

##### Event Definition Layer

```ts
EventGroup + Event
```

* Define typed events using Effect Schema.
* Organize related events into logical groups.

##### Event Journal

```ts
SqlEventJournal
```

* Append-only event storage.
* Sequence-based ordering.
* Supports replay and conflict detection.

##### Identity Management

```ts
publicKey/privateKey
```

* Persistent client identity.
* Enables multi-device synchronization.

##### Event Processing

```ts
EventLog.makeClient(...)
```

* Appends events to the journal.
* Executes associated handlers.
* Supports conflict resolution.

##### Synchronization Layer

```ts
EventLogRemote
EventLogServer
SqlEventLogServer
```

* Pushes local events to remote storage.
* Pulls events from other clients/devices.
* PostgreSQL-backed server implementation.

##### Additional Features

* End-to-end event encryption.
* Reactive state integration.
* Event log compaction.
* Conflict resolution support.

#### Outcome

* Better understanding of event sourcing concepts.
* Improved understanding of Effect's offline-first synchronization model.
* Identified how EventLog can support distributed event synchronization across clients.
